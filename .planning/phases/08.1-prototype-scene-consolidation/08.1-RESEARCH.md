# Phase 8.1 Research: Prototype Scene Consolidation

## Objective
Research the context, requirements, and constraints for Phase 8.1 to prepare a solid plan for porting and stabilizing prototype scenes from the `NAOR_prototype` repository.

## Requirements Covered
- **CORE-03**: User can play consolidated, functional scenes ported from the prototype.
- **CORE-05**: System initializes scenes modularly so they can be played individually in the editor without the main menu.
- **CORE-06**: System integrates mechanics ported from the NAOR_prototype repository cleanly.

## Key Findings & Context

### 1. Missing Dependency (`NAOR_prototype` Repository)
The canonical references state that we must import assets from the `OTK-LAB/NAOR_prototype` repository. However, this repository is currently not present in the workspace or the parent `Projects/` directory.
**Implication for Planning:** The plan must include a step for the user to provide the path to the cloned `NAOR_prototype` repository or clone it directly into the workspace before file migration can begin.

### 2. Architecture Constraints (Ponytail Ultra)
The project strictly follows the "Ponytail Ultra" philosophy:
- **No monolithic global managers** or unnecessary abstractions.
- Native `UnityEngine.SceneManagement` must be used directly for transitions.
- "Minimum that works but incredibly clean and structured."
- No script clutter.

### 3. Contradiction Alert: D-02 vs CORE-05
There is a fundamental contradiction between the stated project decisions and the requirements:
- **REQUIREMENTS.md (CORE-05)**: Mandates that scenes must be playable individually in the editor *without the main menu*.
- **08.1-CONTEXT.md (D-02)**: States "Developers must always start from the Dummy Main Menu to test scenes; no additional fallback/bootstrap scripts (like `#if UNITY_EDITOR`) will be added to individual scenes."
**Resolution Strategy for Planning:** The ban on fallback/bootstrap scripts (D-02) should be maintained to keep the project clean. However, to satisfy CORE-05, we must ensure that ported scenes do not rely on a global bootstrapping process from the Main Menu. Because we are avoiding monolithic managers anyway, all necessary dependencies for a scene should live within that scene natively. This allows scenes to be run individually in the editor (CORE-05) without needing any special `#if UNITY_EDITOR` clutter (respecting D-02).

### 4. Existing Assets & Migration Scope
- The target migration path for the ported scenes is `Assets/Scenes/Prototype/`.
- Care must be taken not to disrupt the `Assets/AI_Tools/` pipeline structure.
- Existing scenes (e.g., `CombatImprovementTest.unity`, `ConsumablesTest.unity`, `MainMenuScene.unity`) exist in `Assets/Scenes/` and should be used as references for the current basic setup.
- The migration requirement (D-01) is absolute: "all level designs and related aspects are brought over completely" ("level designleri vs. her şeyi istiyorum bu tarafa").

## Implications for the Plan
1. **Preparation:** Ask the user to provide the path to `NAOR_prototype`.
2. **Porting Strategy:** Copy scenes, prefabs, and scripts into their strictly categorized directories under `Assets/`.
3. **Refactoring:** Strip out any monolithic global managers inherited from the prototype. Replace them with scene-local setups or direct cross-component references to allow the scene to run standalone.
4. **Verification:** Ensure the ported scenes can be opened and played in the Unity Editor directly without throwing missing dependency errors.
