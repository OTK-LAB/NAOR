## Accomplishments

- `NativeSceneLoader.cs` — drop-in scene loader: `LoadScene(string)`, `ReturnToMainMenu()`, and dual-trigger auto-load (`OnTriggerEnter` + `OnTriggerEnter2D`) for door/zone wiring
- `EscapeToMenu.cs` — single-responsibility Update loop: press Escape → `SceneManager.LoadScene("DummyMainMenu")`, usable in any prototype scene without any UI wiring
- `Phase83Setup.cs` — Editor menu item `Tools > Setup Phase 8.3 (Return Hotkeys)` that iterates all known prototype scenes, injects `EscapeToMenuHook` if absent, and saves each scene automatically

## Decisions Made

- **New Input System for Escape key:** Used `Keyboard.current.escapeKey.wasPressedThisFrame` (InputSystem) over legacy `Input.GetKeyDown(KeyCode.Escape)`. Project already depends on `com.unity.inputsystem`; new API avoids dual-stack issues.
- **Hard-coded scene path list in Phase83Setup:** Safer than iterating EditorBuildSettings at authoring time — explicit list matches known prototype scenes from Phase 8.1 consolidation.
- **Dual trigger methods in NativeSceneLoader:** Supports both 2D and 3D prototype scenes without requiring separate scripts.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Improvement] EscapeToMenu uses InputSystem API instead of legacy Input.GetKeyDown**
- **Found during:** Task 2 (EscapeToMenu implementation)
- **Issue:** Plan specified `Input.GetKeyDown(KeyCode.Escape)` (legacy Input Manager). Project uses `com.unity.inputsystem`; mixing both systems requires "Both" mode in Project Settings, which is fragile.
- **Fix:** Used `Keyboard.current.escapeKey.wasPressedThisFrame` from `UnityEngine.InputSystem` — consistent with the project's existing input stack.
- **Files modified:** `Assets/Scripts/Gameplay/EscapeToMenu.cs`
- **Verification:** File contains InputSystem import and escapeKey reference; no legacy Input.GetKeyDown present.
- **Committed in:** `1c610ee6`
