# Phase 1.1: Directory Structure - Research

## Overview
This phase aims to clean up the Unity `Assets/` directory, moving loose files and disorganized folders into a strict, categorized structure according to the Ponytail Ultra philosophy (minimum that works, incredibly clean and structured).

## Current State of `Assets/` Root
The `Assets/` root currently contains the following items:
- **Game Content (to be moved):** `Animations/`, `Audio/`, `Characters/`, `Environment/`, `Fonts/`, `Idle/`, `Materials/`
- **Third-Party Assets (to be moved):** `Asset Packs/`, `LeanTween/`, `TextMesh Pro/`
- **Target Directories (existing):** `Art/`, `Data/`, `Plugins/`, `Prefabs/`, `Scripts/`, `Settings/`
- **Other/System:** `InputSystem/`, `Resources/`, `Scenes/`
- **Legacy:** `Old Scenes/` (to be deleted)
- **Loose Files:** `PlayerData.json`, `DefaultVolumeProfile.asset`

*Note on ARCH-02:* There are currently **no** loose `.cs` scripts or `.prefab` files sitting directly at the root of the `Assets/` folder. The only loose files are the JSON and asset file mentioned above.

## Implementation Plan Directives (What the Planner Needs to Know)

1. **Move Game Content to `Art/`:**
   - As per **D-01**, move `Characters/`, `Environment/`, `Audio/`, and `Animations/` into `Art/`.
   - *Recommendation:* Also move `Fonts/`, `Idle/`, and `Materials/` into `Art/` as they are visual/game assets and leaving them at the root would violate the clean structure directive.

2. **Move Third-Party Assets to `Plugins/`:**
   - As per **D-02**, move `LeanTween/`, `Asset Packs/`, and `TextMesh Pro/` into `Plugins/`.

3. **Handle Legacy & Loose Files:**
   - As per **D-03**, permanently delete the `Old Scenes/` folder (it's backed up in source control).
   - As per **D-04**:
     - Move `PlayerData.json` to the existing `Data/` directory.
     - Move `DefaultVolumeProfile.asset` to the existing `Settings/` directory.

4. **Unity Specifics:**
   - **CRITICAL:** Every moved file or folder MUST have its corresponding `.meta` file moved alongside it. Failing to do so will break Unity GUIDs and sever asset references.
   - For file deletions (like `Old Scenes/`), ensure the corresponding `.meta` files are also deleted.

## Validation Architecture

### Property-Based Invariants
1. **Assets Root Cleanliness:** The `Assets/` root directory MUST NOT contain any loose files (e.g., `.cs`, `.prefab`, `.json`, `.asset`) or non-canonical folders outside the defined structure (`Art/`, `Data/`, `Plugins/`, `Prefabs/`, `Scripts/`, `Settings/`, `InputSystem/`, `Resources/`, `Scenes/`).
2. **Meta File Parity:** Every file and folder within the `Assets/` directory MUST have an exactly matching `.meta` file alongside it in the same directory.
3. **Legacy Eradication:** The `Old Scenes/` folder and its associated `.meta` file MUST NOT exist anywhere in the active directory structure.

### Held-out Scenarios
1. **Accidental Root File Addition:** A scenario where a new loose asset (e.g., `NewSettings.asset` or `TempScript.cs`) is introduced directly into the `Assets/` root. The validation must flag this violation immediately.
2. **Orphaned or Missing Meta Files:** A scenario simulating a botched merge or move where an asset is moved but its `.meta` file is left behind, or a `.meta` file exists without its corresponding asset. The validation must detect the broken GUID link.

### Observability Requirements
- **Directory Structure Linter Logs:** CI or verification scripts must emit a list of any files or directories found at the `Assets/` root that do not match the strict canonical list.
- **Meta File Match Metrics:** Emitted logs checking `.meta` file parity, reporting the count of orphaned `.meta` files and assets missing `.meta` files (must be 0).
- **Asset Integrity Verification:** A log output verifying that the target directories (`Art/`, `Plugins/`, `Data/`, `Settings/`) contain the expected moved assets, ensuring no files were lost during the move operations.
