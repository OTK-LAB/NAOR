# Pitfalls Research

**Domain:** Unity 2D Scene Integration & UI Menu Systems
**Researched:** 2026-07-12
**Confidence:** HIGH

## Critical Pitfalls

### Pitfall 1: Scene Transition State Bleed (Singleton Abuse)

**What goes wrong:**
Data, audio, or UI from the dummy menu or previous scenes persists incorrectly when loading a new playable scene. For example, UI elements stay on screen, duplicate managers spawn, or events fire multiple times.

**Why it happens:**
Overusing `DontDestroyOnLoad` for managers without proper lifecycle cleanup. Failing to deregister C# events or input actions when a scene unloads.

**How to avoid:**
Implement a strict initialization and teardown sequence per scene. Following "Ponytail Ultra" philosophy: avoid complex persistent singletons. Use simple scene-scoped references where possible. If a persistent SceneLoader is needed, ensure it explicitly cleans up the previous state.

**Warning signs:**
- `MissingReferenceException` in console after scene transitions.
- Duplicate "GameManager" or "AudioSource" objects in the `DontDestroyOnLoad` hierarchy.
- "Start" button requiring double clicks to work after returning to the menu.

**Phase to address:**
v8.0 Scene Selection Menu Implementation

### Pitfall 2: Prototype Bloat Import

**What goes wrong:**
Pulling work from `NAOR_prototype` brings unused legacy assets, duplicate dependencies, broken materials, and messy hierarchies into the strict new architecture.

**Why it happens:**
Drag-and-dropping entire folders or massive prefabs from the old repository instead of surgically extracting only what is needed.

**How to avoid:**
Ponytail Ultra philosophy: Recreate prefabs cleanly from scratch using only the raw assets (sprites, audio) and copy over only essential scripts. Audit every imported script for loose coupling before adding it to the new `Assets` structure.

**Warning signs:**
- Sudden spike in project size or import time.
- Presence of unused `Scripts/Old/` or `Assets/Temp/` folders.
- Warnings about missing scripts on imported GameObjects.

**Phase to address:**
v8.0 Prototype Integration

### Pitfall 3: Broken Editor Workflow (Missing Entry Point)

**What goes wrong:**
Playable scenes crash or throw `NullReferenceException`s if played directly in the Unity Editor without starting from the Dummy Menu scene first.

**Why it happens:**
The playable scene relies on initialization data (e.g., player state, selected options, or instantiated managers) that is only generated by the Dummy Menu.

**How to avoid:**
Implement a safe fallback mechanism. Add a minimal bootstrap script in playable scenes specifically for editor testing (`#if UNITY_EDITOR`), which detects if the required managers are missing and spawns temporary ones.

**Warning signs:**
- Developers constantly having to switch back to `MainMenu.unity` to test a small gameplay tweak.
- Null references on `Awake()` or `Start()` related to GameManagers.

**Phase to address:**
v8.0 Playable Scene Stabilization

---

### Pitfall 4: Hardcoded Scene Loading (Magic Strings)

**What goes wrong:**
Scene transitions break silently when scenes are renamed or moved in the project structure. `SceneManager.LoadScene("Level_1")` fails.

**Why it happens:**
Using raw strings to reference scenes is quick but fragile.

**How to avoid:**
Create a central static registry (e.g., a simple `static class SceneNames` with `const string` fields) or use an Enum-based scene loader to ensure a single source of truth and compile-time safety.

**Warning signs:**
- Strings like `"Playable_Scene_01"` scattered across multiple UI button scripts.
- Console error: `Scene '...' couldn't be loaded because it has not been added to the build settings`.

**Phase to address:**
v8.0 Scene Selection Menu Implementation

## Technical Debt Patterns

Shortcuts that seem reasonable but create long-term problems.

| Shortcut | Immediate Benefit | Long-term Cost | When Acceptable |
|----------|-------------------|----------------|-----------------|
| Using `FindObjectOfType` for scene references | Fast implementation | O(N) performance hit on load, easily breaks if multiple exist | Only in MVP or Editor scripts; never in `Update()` |
| Monolithic GameManager | Easy access to all game state | God object anti-pattern, merge conflicts, impossible to test scenes in isolation | Never (violates clean structure) |
| Connecting UI Buttons via Inspector string methods | No code needed | Silent failures if method is renamed or deleted | Prototyping only |

## Integration Gotchas

Common mistakes when connecting to external services or porting legacy code.

| Integration | Common Mistake | Correct Approach |
|-------------|----------------|------------------|
| Prototype Scripts | Copying scripts that reference obsolete Unity APIs or old packages | Strip scripts down to core logic, rewrite using current project standards |
| Input System | Mixing legacy `Input.GetKeyDown` with New Input System | Standardize on one system (preferably New Input System) and delete legacy code |
| Scene Management | Forgetting to add scenes to Build Settings | Always add dummy menu to Index 0 and playable scenes sequentially; automate via editor script if possible |

## Performance Traps

Patterns that work at small scale but fail as usage grows.

| Trap | Symptoms | Prevention | When It Breaks |
|------|----------|------------|----------------|
| Synchronous Scene Loading | Game freezes completely during transition | Use `SceneManager.LoadSceneAsync` and display a simple loading state | Heavy scenes or mobile builds |
| EventSystem Duplication | UI becomes unresponsive after loading additive scenes | Ensure exactly one EventSystem exists per loaded scene hierarchy | When using additive scenes |

## Security Mistakes

Domain-specific security issues beyond general web security.

| Mistake | Risk | Prevention |
|---------|------|------------|
| Trusting client scene state | Low (Single-player 2D) but leads to bug abuse | Keep critical state in decoupled data containers, not tied to scene lifetime |
| Unsanitized prototype assets | Malicious or corrupt assets breaking Unity editor | Verify source of all prototype files; avoid importing `.dll`s or complex `.unitypackage`s blindly |

## UX Pitfalls

Common user experience mistakes in this domain.

| Pitfall | User Impact | Better Approach |
|---------|-------------|-----------------|
| Instant transition with no feedback | User clicks "Start" and the game freezes before loading | Add a visual click confirmation (button press state) and a minimal fade or "Loading..." text |
| Broken navigation in Dummy Menu | Keyboard/Gamepad users cannot select "Start" | Ensure explicit UI navigation linking is configured in the Unity Canvas |

## "Looks Done But Isn't" Checklist

Things that appear complete but are missing critical pieces.

- [ ] **Scene Transitions:** Often missing asynchronous loading — verify the game doesn't hang on "Start" click.
- [ ] **UI Navigation:** Often missing keyboard/gamepad support — verify you can start the game without a mouse.
- [ ] **Editor Workflow:** Often missing isolated scene testing — verify you can hit Play directly inside a playable scene without crashing.
- [ ] **Event Cleanup:** Often missing event deregistration — verify returning to the dummy menu and starting again doesn't cause duplicated logic.

## Recovery Strategies

When pitfalls occur despite prevention, how to recover.

| Pitfall | Recovery Cost | Recovery Steps |
|---------|---------------|----------------|
| Prototype Bloat Imported | HIGH | Revert commit. Manually inspect and copy specific files, ignoring metadata and prefabs. |
| Corrupt Scene Build State | LOW | Clear Build Settings, re-add scenes starting with Dummy Menu at Index 0. |
| Event Hook Duplication | MEDIUM | Profile memory, find leaked instances, implement `OnDestroy()` teardown across affected scripts. |
